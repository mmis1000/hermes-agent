# Task intent hot-path plan

## Problem

Direct-message task-intent tracking previously used natural-language raw-text phrase/prefix matching (for example English phrases like "also", "instead", "just", or "switch to") to decide whether a user message was a supplement, replacement, or new task. That is brittle, language-specific, and unsafe when text is quoted, historical, generated by a subagent, or merely contains one of those phrases.

## Invariants

1. Raw user text is canonical evidence and must be persisted exactly, subject only to explicit clamping for display.
2. Natural-language prose must not be classified through substring/prefix rules.
3. Only direct external user messages and explicit structured command/system events may mutate canonical task intent.
4. Tool output, web text, subagent reports, compression summaries, session-search results, and assistant prose are advisory/historical only.
5. Ambiguity preserves context. It must not pause, supersede, or clear the active task.
6. Relationship classification and completion validation are separate concerns.

## Hot-path classifier shape

The gateway hot path must not run a full agent turn just to classify intent. If a model judge is later added, it must be a tiny cached micro-classifier:

- no tool schemas,
- no full transcript,
- no persona/SOUL,
- no session-search payloads,
- no subagent context,
- strict JSON only,
- short timeout,
- bounded input/output,
- cache keyed by message id, raw hash, active task id/version, schema/policy/prompt version, and clamp config.

For this implementation pass, the runtime accepts an optional structured `relationship_decision` object and otherwise falls back conservatively.

## Structured relationship decision

Relationship labels:

- `same_task`
- `related_question`
- `supplement`
- `possible_new_task`
- `new_task`
- `replacement`
- `unclear`

State effects:

- `no_change`
- `related_only`
- `append_contract`
- `create_candidate`
- `pause_and_start`
- `supersede`

High-impact state effects (`pause_and_start`, `supersede`) require high confidence and an authoritative source. Low-confidence high-impact decisions are downgraded to `unclear/no_change`.

## Implementation steps

1. Remove phrase/prefix heuristic tables and helper functions from `hermes_cli/task_intents.py`.
2. Add structured `TaskRelationshipDecision` metadata and persist source/message/effect fields on raw task messages.
3. Update `TaskIntentManager.record_direct_message()` to accept optional structured decisions and source metadata; no structured decision means `unclear/no_change` while an active task exists.
4. Remove phrase/prefix inference from `agent/context_compressor.py`; transcript fallback is append-only.
5. Remove compressor phrase-helper calls from gateway continuation/goal-review code; later live user text is preserved additively unless canonical task-intent state says otherwise.
6. Wire gateway direct user message recording with platform message id/source metadata.
7. Update tests so English phrases no longer trigger replacement/supplement automatically; structured decisions do.
8. Add static regression tests so heuristic helper names/prefix tables do not return.
9. Run focused tests and review the diff.

## Follow-up work

- Add the actual bounded/cached micro-judge provider behind a feature flag.
- Move task-intent state to an append-only versioned event log or lineage-aware key so compression child sessions cannot lose state.
- Add a separate completion verifier that checks raw contract + supplements + evidence rather than assistant/todo self-report.
- Expand gateway tests around slash-command metadata boundaries and `/undo`/`/goal` transitions.
